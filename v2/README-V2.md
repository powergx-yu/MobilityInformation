# MobilityInformation v2 — 走廊版（Corridor Version）

v2 是在 v1（保谷专版）基础上的走廊化重构：**皮肤、三页牌面结构和全部牌面规则与 v1 完全一致**，
变化只在「地点可配置」与「牌面由线路模型生成」两点。v1 文件（`../index.html`、`../data/`）未做任何修改，仍在日常使用。

- 文件：`v2/index.html`（单文件、自包含，与 v1 相同形态：锚点时刻表 + 线路模型表全部内联）
- 设置存储键：`ganche_settings_v2`（与 v1 的 `ganche_settings_v1` 分开，互不影响）

## 架构

### 三个可配置地点

设置页把 v1 的「家侧车站 / 公司侧车站」替换为：

| 设置项 | 含义 | 默认值（= v1 现行配置） |
|---|---|---|
| 巴士站（家侧） | 家页左列巴士的发车站 | 保谷庁舎前（→ 保谷駅） |
| 车站 A（家侧车站） | 家页、车站页的电车牌面站 | 保谷（西武池袋線） |
| 车站 B（公司侧车站） | 公司页发车站、家页「推奨」到达站 | 市ヶ谷（有楽町線） |
| 步行时间 ×3 | 家→巴士站 / 公司→B站 / A站→南口巴士站 | 3 / 7 / 3 分钟（口径与 v1 相同） |

车站 A、B 的可选范围（2026-11-26 GAP 1/3 后）：西武池袋線 26 站 + 西武有楽町線（新桜台）+ 有楽町線 24 站
+ **JR 山手線 30 站**，共 81 项（小竹向原在两线交汇处，只列一次，归有楽町線一侧）。池袋在西武/地铁/JR 都有站，
内部按所选线路区分（`S:池袋` / `Y:池袋` / `J:池袋`）；当一侧选西武池袋、另一侧选有乐町线车站时，自动按有乐町线池袋处理（两站步行可达、时刻表以地铁侧为准）。
山手線的牌面与跨社到达推算见下文「JR 山手線」一节。

> GAP 1 的实情（2026-11-26 复查）：设置页选择器的代码自始即列出全部车站——jsdom 实测 A/B 两个
> `<select>` 各 81 个 option（S:27 + Y:24 + J:30）。真机测试时看到的「只有 5 站」是手机原生
> select 弹层一屏可见行数的误读，不是数据缺失。本轮真正的缺口在**牌面生成**：下行方向旧锚点
> （ikeDown）只收录在保谷停车的各停/準急，下行牌面缺全部优等种别、且终点一律显示「飯能方面」。
> 已用池袋全量下行锚点修复（见下）。

### 牌面生成：锚点时刻表 × 线路模型（混合法）

- **锚点牌面**（实测、已验证的逐站时刻表，沿用 v1 的 `data/` 内联数据）：
  保谷上行全量表（seibuUpFull）、池袋下行（ikeDown，仅保谷停车车，保留作接续/实测到达用）、小竹向原下行（kotakeDown）、
  市ヶ谷有乐町线上行（metro）、池袋有乐町线下行（metroIkeDown）。
- **池袋下行全量锚点**（2026-11-26 GAP 1 新增，`DATA.ikeDownFull`，来源 Yahoo!乗換案内 池袋站时刻表）：
  平日 321 班（各停 159 / 準急 66 / 急行 56 / 特急 28 / 快速 12，逐车带真实终点），土曜=休日 289 班。
  下行牌面改由全量锚点按模型累积平移生成：豊島園行只经練馬以东、西武球場前行只经所沢以西、
  其余按终点站判定经由；逐车显示真实终点（不再是清一色「飯能方面」）。
  保谷站的下行牌面优先采用旧锚点的实测到达时刻 `arr_hoya`（照合结果见验证一节）——
  实测发现各停的模型累积（池袋→保谷）比实测短 2 分，準急则与实测逐分一致。
- **线路模型**（`data-v2/seibu-ikebukuro-model-v2.json`、`data-v2/yurakucho-model.json`，构建时内联为 `MODEL_TABLES`）：
  每种列车种别的停站模式 + 停站间运行时间。非锚点站 X 的牌面 = 最近锚点牌面按「该种别在锚点→X 的累积时分」逐车平移，
  并按种别停站模式重新判定该车在 X 是否停车（通过车照常以小字通过行显示）。
  跨越非停站的长区间按其覆盖的各停基础区间的比例分配到中间各站（与模型报告的校验口径一致）。
- **方向判定**：用各停累积时分作走廊坐标（有乐町线在小竹向原处接续），A→B 坐标增 = 上行方向。
- **到达推算**：
  - 同线：发车 + 两站间该种别累积时分差。
  - 西武→有乐町线：直通车经练马支线到小竹向原再接有乐町线累积；池袋终着车在池袋换乘（缓冲 4 分，用池袋锚点下行表）；
    小竹向原终着车在小竹向原换乘（缓冲 2 分，用池袋锚点表镜像，镜像偏移取模型累积 7 分）。
  - 有乐町线→西武：沿用 v1 公司页的逐车接续逻辑（直通车在小竹向原与下行表对接，窗口 −1～+5 分；
    石神井公園终着车走石神井接续，窗口 +2～+32 分；池袋终着车走池袋下行表，窗口 +4～+34 分），目标站从保谷推广到任意西武站。
  - 公司页 B=池袋（西武下行锚点）时，到保谷的到达时刻直接用锚点实测 `arr_hoya`，与 v1 完全一致。

### JR 山手線（2026-11-26 GAP 3 新增）

- **数据**：JR 东日本官方全线时刻表（基于《JR時刻表》2026 年 12 月号）逐站抽取——30 站 × 内回り/外回り ×
  平日/土曜・休日（JR 只公布这两种日型，app 内 saturday 与 holiday 共用土休表），每站约 246–263 班，
  逐车带终点（大崎/品川/池袋三种短交路）。另有区间中位时分环线模型（内回り一周 ≈64 分、外回り ≈65 分）
  只用于到达推算与方向判定，不参与发车时刻生成——**山手線牌面是逐站实测表，不是平移生成**。
- **方向判定**（A、B 都是山手線站时）：先按区间时分取较短方向，再用「该方向 3 小时内是否有车真正到达 B」
  校验（`jrDirFor`）——例如田町→池袋：外回り 31 分 < 内回り 33 分，但外回り短交路车多在大崎/品川终着，
  校验会落到真正能到的方向。大崎终着按**贯通运行**处理：全线表的列以大崎为一圈的切分点，
  旅客运行实际穿过大崎继续下一圈（駅探的渋谷→田町直通清单与内回り全列车逐分一致，可证），
  故大崎行按「再绕一周可达」判定；品川/池袋终着是真实短交路，严格判定。
- **跨社接续**：山手線与走廊之间只经池袋换乘，沿用 v1/v2 的窗口纪律（西武/地铁→池袋后缓冲 5 分、
  34 分窗口内取第一班真正到达 B 的山手線车；反方向缓冲 4 分、窗口 34 分），窗口外不显示（无幻影接续）。
  福户线直通保谷→渋谷这类经路不在建模内（与既有福户线处理同族）。
- **到达时刻精度**：区间中位时分与全天追踪列车对照，多数区间逐分一致，个别 ±1–2 分
  （品川→大崎外回り一段中位值比追踪慢约 1.5 分）——与西武模型同一精度口径（±数分）。

### 保留的 v1 规则（逐条核对过）

- 推奨：直通优先，换乘方案必须早到 ≥15 分钟才胜出；物理第一班（到站 +1 分进站缓冲）与推奨分开显示。
- 营业日界：相邻班次间隔 >90 分截断，牌面不跨夜滚入次日；车站页/公司页巴士同口径。
- 深夜接续窗口：直通 5 分 / 小竹向原・石神井 32 分 / 池袋 34 分，窗口外的「接续」视为次日班次并丢弃（无幻影接续）。
- 车站页：刚发车行（≤5 分）、停车车次 6 班上限、⇅ 上下翻转、巴士余裕分钟（已扣站台步行）。
- 紧凑单屏节奏、fit/zoom 处理、EVA 皮肤、ODPT 延误查询（设置了 key 时）。

## 已知限制（锚点平移法的固有边界，不臆造列车）

1. **锚点盲区**：在锚点站与目标站之间始发的列车，锚点牌面上不存在，无法生成。
   典型：保谷始发的各停（下行方向把保谷当目标站往西看时同理）。
   ~~池袋下行锚点只收录保谷停车车、下行牌面缺优等种别~~ —— 已于 2026-11-26 由全量下行锚点修复（见架构一节）；
   **上行方向同类盲区仍在**（上行锚点是保谷全量表，保谷以西始发、保谷以东才出现的车次结构上仍不可见的部分以模型口径为准）。
2. **地铁下行锚点无逐车终点**：metroIkeDown 不记录每班车的终点（新木場/豊洲/和光市等），
   新木場方向牌面一律标「新木場」行；中途终着的车会被当作开往新木場显示。
3. **东武直通车**：和光市方向牌面中的川越市/森林公園/志木行按「小竹向原换乘类」处理（与 v1 口径相同）。
